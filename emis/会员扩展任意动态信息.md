## 💾 数据模型与序列化架构 (Zero-Risk DB Serialization)

由于数据库的 `notes` (备注) 字段为 `TextField` 且容量巨大，我们利用此字段存储打包的结构化扩展字段 JSON 字符串，而无需对 MySQL 表实体和迁移做任何高风险更改。

### 1. JSON 报文范例
```json
{
  "text": "常规备注内容（由管理员填写的传统备注）",
  "customFields": [
    { "key": "职务", "value": "技术总监" },
    { "key": "微信", "value": "wechat_888" },
    { "key": "邮箱", "value": "admin@emis.org" }
  ]
}
```

### 2. 前端编解码解析器 (Helper Functions)
我们在页面中加入两组安全的、具备完全向下兼容能力的编解码转换器：
```typescript
interface CustomFieldItem {
  key: string;
  value: string;
}

interface ParsedNotes {
  text: string;
  customFields: CustomFieldItem[];
}

/**
 * 健壮的解码器（容错处理已有的普通文本老数据）
 */
const parseNotes = (notesStr: string): ParsedNotes => {
  try {
    const parsed = JSON.parse(notesStr);
    if (parsed && typeof parsed === 'object' && ('text' in parsed || 'customFields' in parsed)) {
      return {
        text: parsed.text || '',
        customFields: Array.isArray(parsed.customFields) ? parsed.customFields : [],
      };
    }
  } catch (e) {
    // 解析失败代表是原有的普通文本老数据，直接作为常规备注，自定义字段为空
  }
  return {
    text: notesStr || '',
    customFields: [],
  };
};

/**
 * 健壮的编码器
 */
const serializeNotes = (text: string, customFields: CustomFieldItem[]): string => {
  return JSON.stringify({
    text: text || '',
    customFields: customFields || [],
  });
};
```

## 🎨 前端动态加框 UI/UX 布局

1. **弹窗布局增加「扩展可选字段区」**：
   在常规的姓名、手机号等必填字段下方，新增卡片包围的扩展信息区域。
2. **“+ 添加自定义字段”核心交互**：
   * 页面底端呈现 `[+ 添加自定义属性]` 按钮。
   * 点击时弹出小输入框/选择器，支持快捷选择 `职务`、`微信`、`邮箱`，也支持管理员直接手打输入新属性（如 `QQ`、`会员等级`）。
   * 确定后立刻在表单渲染一行：`[字段名] ── [输入框] ── [红叉删除按钮]`。
   * 移除时，点击行尾的 `[红叉删除]` 按钮，即可无缝从表单行中踢出。
3. **后台会员列表列表展示联动**：
   在表格的“备注说明”列中，系统自动将这组扩展属性解码，并渲染为高颜值的彩色小徽标 Tag。
