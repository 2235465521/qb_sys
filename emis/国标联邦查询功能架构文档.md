# EMIS 实时联邦查询功能开发与架构文档

## 一、功能背景与架构演进
在企业管理信息系统（EMIS）中，企业除了自有“企业标准”外，往往会参与起草或主导大量的“国家标准”、“行业标准”等外部权威标准。这些海量历史标准数据目前存放在独立的 `STSC_standard_database` 主元数据库中。

为了避免传统的“数据搬运/ETL同步”带来的数据高度冗余、全量同步延迟、以及对系统原有 1:N 关系数据库模型的侵入破坏，我们设计并实施了**“实时联邦查询架构 (Real-time Federated Query)”**。

## 二、架构核心思想
遵循 **单一数据源 (SSOT)** 原则：
- EMIS 本地数据库 (`emis_db`) **不存储**任何国标、行标的副本。
- 后端作为“数据网关”，在收到企业查询请求时，**实时跨库**对 `STSC_standard_database` 发起高性能 SQL 检索。
- 在内存中完成脏数据容错清洗后，与本地数据融合并统一向前端输出 JSON。

## 三、修改的模块与代码逻辑清单

### 1. 核心配置: 多数据库路由 (`emis/backend/config/settings.py`)
利用 Django 多数据库特性增加连接池，允许系统同时操作主库和本库：
```python
'stsc_db': {
    'ENGINE': 'django.db.backends.mysql',
    'NAME': config('STSC_DB_NAME', default='mydate'),
    'USER': config('STSC_DB_USER', default='root'),
    'PASSWORD': config('STSC_DB_PASSWORD', default=''),
    'HOST': config('STSC_DB_HOST', default='127.0.0.1'),
    'PORT': config('STSC_DB_PORT', default='3306'),
    'OPTIONS': {'charset': 'utf8mb4'},
}
```

### 2. 脏数据清洗与联邦查询核心引擎 (`emis/backend/companies/views/standard_sync_views.py`)
新建了独立接口：`CompanyFederatedStandardsAPIView`
- **高性能跨表直连**：绕过 Django ORM 的内存消耗，直接执行 `unit_dict` -> `std_unit_relation` -> `view_std_full` 的三表联合查询，毫秒级定位指定企业的起草历史。
- **数据容错提取 (`LIKE` 引擎)**：历史爬虫导致 `unit_dict` 或起草人字段常常将多单位黏连（如 `公司A、公司B等`），系统使用 `LIKE '%公司名%'` 进行宽容匹配，确保精准摘取。
- **正则极度清洗算法 (`clean_draft_units`)**：接口内置清洗函数，利用正则表达式一键替换多重不规范标点（中文逗号、分号、顿号），并**彻底剥离并删除了夹杂的“等”字**，向前端稳定输出干净的字符串数组。

### 3. API 路由挂载 (`emis/backend/companies/urls/admin_urls.py`)
将开发好的高性能接口注入了 Django 的路由系统：
- 注册接口：`/api/admin/companies/<id>/federated_standards/`
- 提供无缝的 RESTful 支持。

## 四、服务端部署指南 (针对阿里云 ECS)
1. 在生产环境服务器拉取 Github 的 `main` 分支最新代码。
2. 修改服务器目录下的 `emis/backend/.env`：
   ```ini
   STSC_DB_NAME=STSC_standard_database
   STSC_DB_PASSWORD=您的真实密码
   STSC_DB_USER=root
   ```
3. 使用 PM2 或 Docker Compose 重启后端 Django 服务。
