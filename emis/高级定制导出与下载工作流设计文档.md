# EMIS 高级定制导出与下载工作流说明文档

本文档详尽描述了企业管理信息系统（EMIS）本次升级中新增的 **“企业高级定制导出”** 与 **“多类型标准下载/导入工作流”** 的后端 API 逻辑与前端 React 组件设计。

---

## 第一部分：高级定制导出（Advanced Custom Export）

本功能允许管理员在后台“企业信息管理”表格中，按需勾选需要导出的字段列（包含原有的基本信息与新增的 16 个深度详情字段），并支持选择是否级联导出每家企业关联的所有标准目录。

### 一、 后端 API 设计

#### 1. 导出 API 端点
- **URL**: `/api/admin/companies/export/`
- **Method**: `GET` 或 `POST` （推荐使用 `POST` 以支持传输较多的字段名）
- **Authentication**: JWT Bearer Token

#### 2. 请求载荷（POST Body）或 URL 参数（GET Query）
- `fields`: 字符串数组，指定需要导出的列标识符。若为空或未传，默认导出全部 28 个字段。
  - **支持的可选字段列表**：
    - `'name'` (企业名称), `'credit_code'` (统一社会信用代码), `'legal_person'` (法人), `'province'` (省份), `'city'` (城市), `'district'` (区县), `'latitude'` (纬度), `'longitude'` (经度), `'contact'` (联系方式), `'address'` (详细地址), `'status'` (状态), `'created_at'` (入库时间)
    - `'established_date'` (成立日期), `'registered_address'` (注册地址), `'registered_zipcode'` (注册地址邮编), `'valid_mobile'` (有效手机号), `'more_phones'` (更多电话), `'email'` (邮箱), `'company_type'` (企业(机构)类型), `'registration_no'` (注册号), `'organization_code'` (组织机构代码), `'industry_category'` (国标行业门类), `'industry_major'` (国标行业大类), `'industry_middle'` (国标行业中类), `'industry_minor'` (国标行业小类), `'company_size'` (企业规模), `'english_name'` (英文名), `'former_names'` (曾用名)
- `include_standards`: 布尔值（`true` / `false`），是否连带查出企业关联的所有标准并附在表格末尾。

#### 3. 核心后端技术特征
- **N+1 性能优化**：当 `include_standards=True` 时，底层通过 `prefetch_related('standards')` 一次性拉取关联数据，将多行级联的 SQL 查询复杂度降低到 O(1)。
- **中文排版自适应**：在利用 `openpyxl` 生成二进制数据流时，通过 `unicodedata.east_asian_width` 区分中英文字符宽度。同时对有多行换行符的长单元格（如包含几十个国标行标的“标准目录”）只取其单行最宽处，既防止列宽无限变宽，又保留了自动换行的美感。

### 二、 前端组件设计

#### 1. 高级导出配置 Modal（`ExportConfigModal`）
- **位置**：[index.tsx](file:///e:/企标管理系统_企标记录/emis/frontend/src/pages/Admin/Companies/index.tsx) 中。
- **页面交互**：
  - 点击“批量导出”时弹出。
  - **多选配置（Checkbox.Group）**：以 `Row` + `Col` 栅格化排版展示 28 个可选属性。
  - **全选控制（Checkbox）**：支持一键勾选所有字段或清空。
  - **标准级联开关（Switch）**：显示“是否同时导出该公司关联的标准目录”。
- **文件流下载处理**：
  - 通过 `apiClient.post` 提交筛选参数及字段名配置，设定 `responseType: 'blob'`。
  - 导出成功后在内存中生成 `window.URL.createObjectURL(blob)`，通过动态创建 `<a>` 标签模拟浏览器物理下载。

## 第二部分：下载工作流优化（Download Workflow）

客户端“标准资源检索”界面中，查看企业关联标准与一键打包下载的完整工作流。

### 一、 后端 API 设计

#### 1. 多类型模板生成接口
- **URL**: `/api/admin/standards/import/template/`
- **Method**: `GET`
- **Query Parameter**: `type` (`enterprise` / `national` / `industry` / `local` / `group`)
- **Response**: 二进制 Excel 文件流
- **逻辑**：根据类型参数输出不同表头。企标额外输出工商与法人列，国行地标等包含 ICS/CCS 以及起草单位级联匹配列。

#### 2. 多类型标准批量导入接口
- **URL**: `/api/admin/standards/import/`
- **Method**: `POST`
- **Payload**: Form-Data 上传的 Excel 附件
- **Query Parameter**: `type`
- **逻辑**：非企标类型导入时，如提供关联起草企业（包含企业名称或信用代码），后端会自动利用 UUID 生成虚拟信用代码，创建并补全占位企业；导入后会自动触发共享磁盘的 PDF 文件对齐。

#### 3. 打包下载 API（异步排队机制）
- **第一步：创建打包任务**
  - **URL**: `/api/client/standards/pack/`
  - **Method**: `POST`
  - **Body**: `{ "standard_ids": [1, 2, 3] }`
  - **Response**: 返回任务 `token`。
- **第二步：任务状态轮询**
  - **URL**: `/api/client/standards/pack/{token}/status/`
  - **Method**: `GET`
  - **Response**: 返回状态（`pending` / `running` / `done` / `failed`）及 `download_url`。
- **物理磁盘优化**：ZIP 任务在 Celery 异步线程中读取平铺的 `SHARED_DISK_ROOT` 共享盘文件，减少本地物理内存占用。

### 二、 前端组件设计

#### 1. 分类筛选与当前列表全选
- **位置**：[StandardDrawer.tsx](file:///e:/企标管理系统_企标记录/emis/frontend/src/pages/Client/Search/components/StandardDrawer.tsx)
- **Tabs 结构**：展示“全部”、“企标”、“国标”、“行标”、“地标”、“团标”标签，附带数量展示。
- **全选算法**：在前端过滤出 `filteredStandards` 后，全选按钮只对当前 Tab 过滤所得的 ID 集合进行并集 `Set` 合并或差集剔除。

#### 2. 下载确认清单 Modal (类似购物车)
- 用户在 Drawer 中勾选要打包的标准，点击“打包下载”时，系统**拦截**当前下载。
- 弹出一个 `ShoppingCartOutlined` 清单模态框：
  - 清单中列表展示所有已选标准的编号、标题和类型标签。
  - 每行右侧包含“垃圾桶”删除图标，点击可从已选集合中删除此文件。
  - 底部左侧提供“清空列表”按键。
  - 右侧提供“继续添加”（关闭模态框返回 Drawer）和“确认打包下载”按钮。
- 用户确认无误后点击“确认打包下载”，系统调用后端异步 ZIP 任务，并结合 Antd `Progress` 进度条组件，以 2 秒频率轮询状态接口，直到下载自动拉起。
