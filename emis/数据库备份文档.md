# EMIS 系统数据库自动备份配置文档

本配置文档详述了如何为部署在 `192.168.10.225` 服务器上的 `STSC_standard_database` 数据库配置自动定期备份，并将备份文件安全存放在共享磁盘阵列（挂载点为 `/mnt/std_bk/磁盘阵列/`）上。

---

## 备份方案设计

1. **备份周期**：每 3 天的凌晨 2:00（低流量时段）自动执行。
2. **备份存储路径**：`/mnt/std_bk/磁盘阵列/db_backups/`（物理磁盘阵列上，防止服务器系统盘损坏导致数据丢失）。
3. **保留策略**：本地及磁盘阵列仅保留最近 30 天的备份，更早的备份会自动清理，避免占满存储空间。
4. **安全性**：使用 `~/.my.cnf` 文件配置凭证，避免明文密码写入脚本或出现在系统进程历史记录中。

---

## 具体配置步骤

### 1. 登录服务器
使用 SSH 工具登录到目标服务器：
```bash
ssh zkbz01@192.168.10.225
```

### 2. 配置安全免密凭证
在当前登录用户（如 `zkbz01`）的家目录下创建客户端配置文件 `~/.my.cnf`：
```bash
nano ~/.my.cnf
```
在文件中添加以下配置（**请根据实际情况修改数据库连接信息与密码**）：
```ini
[client]
user=root
password=lsj223546
host=127.0.0.1
port=3306
```
保存并退出，然后修改该文件权限（MySQL 客户端强制要求该文件权限必须为 600，否则会忽略此配置）：
```bash
chmod 600 ~/.my.cnf
```

### 3. 在磁盘阵列上创建备份目录
在挂载的物理磁盘阵列上创建专用备份文件夹，并配置好读写权限：
```bash
# 创建备份目录
sudo mkdir -p "/mnt/std_bk/磁盘阵列/db_backups"

# 将所有权赋予当前运行备份的普通用户（例如 zkbz01）
sudo chown -R zkbz01:zkbz01 "/mnt/std_bk/磁盘阵列/db_backups"
```

### 4. 编写备份脚本
在用户家目录下创建备份脚本 `~/backup_stsc_db.sh`：
```bash
nano ~/backup_stsc_db.sh
```
粘贴以下完整脚本代码：
```bash
#!/bin/bash

# 备份目标路径（磁盘阵列）
BACKUP_DIR="/mnt/std_bk/磁盘阵列/db_backups"
# 待备份的数据库名称
DB_NAME="STSC_standard_database"

DATE=$(date +%F_%H%M%S)
BACKUP_FILE="${BACKUP_DIR}/${DB_NAME}_backup_${DATE}.sql.gz"

# 确保目标目录存在
mkdir -p "$BACKUP_DIR"

# 开始备份并压缩（已配置 ~/.my.cnf，免密码输入）
mysqldump --databases "$DB_NAME" | gzip > "$BACKUP_FILE"

# 验证备份是否成功
if [ $? -eq 0 ]; then
    echo "[$(date)] 数据库备份成功: ${BACKUP_FILE}"
else
    echo "[$(date)] 数据库备份失败！"
fi

# 自动清理 30 天以前的旧备份
find "$BACKUP_DIR" -name "${DB_NAME}_backup_*.sql.gz" -mtime +30 -exec rm -f {} \;
```
保存退出，并给脚本赋予执行权限：
```bash
chmod +x ~/backup_stsc_db.sh
```

### 5. 手动测试验证
在正式启用自动任务前，建议手动执行一次测试脚本：
```bash
~/backup_stsc_db.sh
```
执行完毕后，检查备份目录以确认文件正常生成：
```bash
ls -lh "/mnt/std_bk/磁盘阵列/db_backups"
```

### 6. 配置 Cron 定时任务
编辑当前用户的定时任务列表：
```bash
crontab -e
```
在文件末尾添加以下一行配置，代表**每 3 天的凌晨 2:00** 自动执行一次备份：
```text
0 2 */3 * * /bin/bash /home/zkbz01/backup_stsc_db.sh >> /home/zkbz01/backup_db.log 2>&1
```
> **注意**：如果当前用户的家目录不是 `/home/zkbz01`，请使用实际的绝对路径替换 `/home/zkbz01/backup_stsc_db.sh`。

---

## 灾难恢复指南

如果遇到数据损坏或需要进行版本回滚，可以通过以下步骤恢复数据：

```bash
# 1. 解压备份好的压缩包
gunzip -c /mnt/std_bk/磁盘阵列/db_backups/STSC_standard_database_backup_xxxxxx.sql.gz > ~/temp_restore.sql

# 2. 导入数据到数据库中
mysql STSC_standard_database < ~/temp_restore.sql

# 3. 恢复成功后清理临时解压缩的 SQL 文件
rm ~/temp_restore.sql
```
