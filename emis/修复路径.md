# EMIS 文件架构重构 + 批量下载修复计划

## 背景

项目有 10w+ 企标 PDF 文件，全部存放在磁盘阵列 `Y:\磁盘阵列\标准文件下载\企标下载\整合\`。
文件**绝对不能**进入项目的 `media/` 文件夹（会撑爆项目）。
Nginx 已启动，可使用 `X-Accel-Redirect` 高性能安全下载。

---

## 已确认的关键信息

| 项目 | 值 |
|------|-----|
| 磁盘阵列路径 | `Y:\磁盘阵列\标准文件下载\企标下载\整合\` |
| 磁盘文件名格式 | `Q_QJSB_JS022-2016_置物架2-unlocked.pdf` |
| DB `clean_id` 格式 | `Q/QJSB JS022-2016` |
| 映射规则 | `clean_id` 中 `/` → `_`，空格 → `_`，再前缀匹配磁盘文件名 |
| 旧 media/pdfs 文件 | 直接废弃（数据库 pdf_file 字段清空后重建） |
| Nginx 状态 | 已启动，支持 X-Accel-Redirect |

---

## 根本原因分析

### Bug 1：前端下载URL双重 `/api/` 前缀
```
实际请求: GET /api/api/client/standards/pack/download/?token=xxx  → 404
正确应该: GET /api/client/standards/pack/download/?token=xxx
```
前端在拼接 download_url 时，把 `apiClient.defaults.baseURL`（含 `/api`）和已含 `/api/` 的路径叠加了。

### Bug 2：ZIP打包文件找不到
`create_zip_from_standards` 中判断路径以 `整合/` 开头才走磁盘阵列，
但数据库中存的是 `pdfs/2026/05/19/xxx.pdf`（旧格式），导致走 `std.pdf_file.path` 找本地 media 文件 → 文件不存在 → 跳过 → ZIP 为空。

### Bug 3：`Standard.pdf_file` 字段语义错误
现在存的是 Django `FileField`，指向 `media/pdfs/...` 内部路径。
正确做法：只存磁盘阵列上的**文件名**（`CharField`），不用 `FileField`。

## 正确架构

```
磁盘阵列 Y:\...\整合\xxx.pdf   ← 原始文件，永不移动，永不进项目
         ↓
数据库 Standard.disk_filename = "Q_QJSB_JS022-2016_置物架2-unlocked.pdf"
         ↓
用户点击下载
         ↓
Django: 验权 → 返回 X-Accel-Redirect: /protected_shared_disk/整合/xxx.pdf
         ↓
Nginx: 读取磁盘阵列文件 → 高速流式传输给用户

批量ZIP:
Celery → 直接遍历磁盘阵列文件 → 内存打包 → 临时存 media/temp_zips/ → 用户下载 → 自动清理
```

disk_filename = "整合/Q_QJSB_JS022-2016_置物架2-unlocked.pdf"
为什么存相对路径，不存完整路径？
方案	值	问题
❌ 完整路径	Y:\磁盘阵列\标准文件下载\企标下载\整合\xxx.pdf	盘符写死，换机器或盘符变了全部失效
✅ 相对路径	整合/xxx.pdf	只需在 settings.py 改一处根目录配置即可
三者如何联动？


数据库存储:
  disk_filename = "整合/Q_QJSB_JS022-2016_置物架2-unlocked.pdf"
Django 单个下载:
  完整磁盘路径 = SHARED_DISK_ROOT + "/" + disk_filename
             = Y:\磁盘阵列\标准文件下载\企标下载\ + 整合/Q_xxx.pdf  ✅
Nginx X-Accel-Redirect:
  Header = /protected_shared_disk/整合/Q_xxx.pdf
  Nginx alias 映射: /protected_shared_disk/ → Y:\...\企标下载\
  实际读取文件: Y:\...\企标下载\整合\Q_xxx.pdf  ✅
ZIP 打包:
  Celery 直接拼完整路径读取 → 打包进内存 → 用户下载  ✅
settings.py 只需一个配置
