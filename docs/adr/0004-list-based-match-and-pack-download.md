# 4. 基于外部清单（文本粘贴与Excel）智能降级匹配打包下载设计

Date: 2026-10-09

## Status

Accepted

## Context

在企标管理系统（EMIS）中，用户（如标准化工程师、合规审查员、质检机构人员）经常持有离线业务清单（手头已有包含企业标准号或标准名称的 Excel 表格或文字清单），急需将对应企标的 PDF 全文批量提取打包下载。

现有系统仅支持通过关键词检索过滤后的“整页全选”或“按检索条件抽样打包”，缺少直接输入外部清单进行精准批量提取的能力，用户被迫逐条搜索勾选，效率极低。在引入外部清单匹配时面临以下核心挑战：
1. **多重匹配与歧义**：标准号通常唯一，但若标准号未命中而降级至标准名称匹配时，存在全国多家企业同名标准、或同一企业多历史版本的问题。若全量打包会导致压缩包体积失控，若随机截断则可能遗漏现行版本；
2. **输入源异构性**：用户既可能直接从表格中复制多行文本（纯编号、纯名称或制表符分隔的多列），也可能直接上传结构各异的 Excel 文件（表头位置与列名五花八门）；
3. **交付审计与对账断层**：用户下载压缩包后需要明确知道哪些标准已成功打包、哪些标准库内未收录或缺少 PDF 电子档。

## Decision

我们决定在「搜索企标」页面（`SearchStandards`）中设计并落地**基于外部清单的智能匹配打包下载系统**：

1. **两阶段匹配预览流（Two-Phase Flow）**：
   - 第一阶段（无锁轻量预匹配）：用户粘贴文本或上传 Excel 后，前端调用轻量预匹配接口，秒级在弹窗内呈现匹配统计与状态明细（成功命中数、含 PDF 文件数、未收录数、无文件数）；
   - 第二阶段（异步任务提交）：用户核对无误后点击「确认打包下载」，系统锁定有效标准 ID，交由后端 Celery 异步队列压制打包。

2. **双层降级与消歧择优策略（Fallback & Disambiguation Policy）**：
   - **主键优先**：逐行优先使用“标准编号”进行清洗正规化匹配（`clean_id` / `standard_no`）；
   - **名称降级**：若标准编号未命中或为空，自动降级至“标准名称”（`title`）进行匹配；
   - **多重匹配收敛**：若标准名称命中多条企标记录，按优先级级联单项截取最优版本：
     `有效 PDF 附件优先` → `现行有效状态（status='active'）优先` → `最新发布日期（publish_date）倒序`。

3. **操作栏统一入口与双 Tab 向导（Unified Entry & Wizard Modal）**：
   - 在毛玻璃操作栏【打包下载】旁新增次主按钮 `[📋 按清单批量下载]`；
   - 弹窗内设 **Tab 1（文本批量粘贴）** 与 **Tab 2（上传 Excel 文件）**；
   - Excel 上传采用**智能正则嗅探**（扫描前 5 行自动预选标准编号列与标准名称列），辅以**轻量可视化下拉映射**兜底容错。

4. **双通道交付审计回执（Audit Manifest Delivery）**：
   - 预览阶段支持一键点击 `[📥 导出匹配明细表 (.xlsx)]`，实时获取审计对账清单；
   - 后台 Celery 打包时，自动在 ZIP 压缩包根目录下注入一份《企标打包下载清单与未命中明细.xlsx》，彻底解决对账难题。

5. **文件命名规整与安全批次上限**：
   - ZIP 包内 PDF 文件统一清洗重命名为：`[标准编号] 标准名称.pdf`（自动转义 Windows 非法字符 `/` 为 `_`）；
   - 单次匹配批量上限设定为 500 条，与系统 Celery 任务队列吞吐能力对齐。

## Consequences

### Positive
- **闭环体验极致平滑**：兼顾了粘帖即用的轻量感与 Excel 上传的高吞吐，用户从导入到打包一气呵成；
- **业务对账零误差**：通过消歧策略确保下载到的是最新有效版本，通过双通道回执明确未收录及缺档明细；
- **工程稳健可控**：两阶段架构避免了大体积盲目打包，规整命名彻底杜绝跨平台解压乱码与路径冲突。

### Negative / Trade-offs
- 需要在 Celery 打包任务中动态生成临时 Excel 清单并追加进 ZIP 流，带来微量的 CPU/内存开销，但相比打包数十兆 PDF 文件的耗时可忽略不计。
